# Production Offline RAG Course Blueprint Design

日期：2026-07-29
状态：已形成当前认可的终局设计，待按本设计更新课程蓝图与世界地图

## 1. 目标

为 `offline-rag-go-lab` 建立一版完整、可执行、可继续修订的课程蓝图。

这版蓝图必须同时回答：

1. 现有课程已经实现和学习到哪里。
2. 下一节为什么是下一节。
3. 从 L34 开始还需要补齐哪些生产能力。
4. 什么证据允许一节课或一个阶段被标记为完成。
5. 当前定义下，什么状态才可以称为“生产级离线 RAG”。

蓝图不是最终永远不变的承诺。它是当前经过完整推演后采用的主航线；后续只有新的真实
需求、Golden Dataset 结果、故障证据或部署约束，才能驱动蓝图调整。

## 2. 当前终局

课程当前终点定为 L78。

L78 完成时，仓库应形成一个可部署在 Linux 单机或小型内网环境中的离线 RAG 系统：

- 模型和依赖资产可离线准备、校验并重复部署。
- 文档能够导入、更新、删除、重建和追溯。
- 检索质量由版本化数据集衡量，不靠主观样例判断。
- 回答能够引用证据，并在证据不足时拒答。
- recent window、session summary、long-term memory 和 document retrieval 能共同工作。
- 用户、记忆和知识域之间保持强隔离。
- MySQL、Qdrant、Ollama 或后台任务失败时有确定的降级、重试和恢复行为。
- 系统具备日志、指标、追踪、备份、恢复、升级、回滚和运行手册。
- 最终验收覆盖冷启动部署、真实导入、并发对话、质量回归、故障演练、恢复和升级回滚。

当前终局不包含：

- 公网 SaaS 平台和计费系统。
- Kubernetes、多地域和互联网规模分布式架构。
- 复杂管理前端或终端用户 UI。
- 基础模型训练、微调平台或 GPU 集群调度平台。
- 为没有真实需求的格式、模型和中间件提前建立通用框架。

## 3. 课程组织方法

采用“端到端能力关卡”，不采用单纯的组件穷举。

每个阶段必须：

1. 解决一个完整的生产能力问题。
2. 明确依赖的前置课程。
3. 产生可运行或可检查的实践产物。
4. 用自动测试、Golden Dataset、真实服务验证或恢复演练建立门禁。
5. 说明本阶段故意不解决的内容。

L34 之后保持每五节一个阶段。这既延续现有五节一批的实践方式，也让每个阶段能够独立
设计、实现、审核和提交。

## 4. 文档职责

### 4.1 权威蓝图

新增 `docs/teaching/00-course-blueprint.md`，作为课程顺序和阶段定义的唯一权威来源。

它负责：

- L01-L78 的连续编号。
- 每节的主题、状态、依赖、实践产物和验收证据。
- 每个阶段的目标、门禁和非目标。
- 终局验收定义。

### 4.2 世界地图

更新 `world/game-world-map.md`，作为面向快速理解的入口。

它负责：

- 用简洁语言说明系统是什么。
- 展示已开放、正在学习、计划建设的区域。
- 概括 L01-L78 阶段地图。
- 链接到权威蓝图和当前学习状态。

它不再复制所有逐课验收细节，也不再把早期 gateway demo 当成整个项目的当前状态。

### 4.3 学习状态

更新 `docs/teaching/00-learning-status.md`。

它只负责动态状态：

- 已学到哪里。
- 已实现到哪里。
- 下一次教学从哪里开始。
- 指向权威蓝图。

阶段和课程定义不得在这里重新发明。

### 4.4 优化 Backlog

保留 `docs/teaching/00-optimization-backlog.md` 作为证据尚不足的候选池。

Backlog 项进入正式课程必须满足至少一个条件：

- Golden Dataset 显示明确质量缺口。
- 真实运行出现可复现故障或容量问题。
- 生产终局存在不可绕过的安全、数据完整性或运维要求。
- 它是后续已批准课程的必要前置能力。

已经进入 L34-L78 的条目应在 backlog 中标注对应课程，避免两处重复表达为“待决定”。

## 5. 状态模型

每节课只允许使用以下状态：

- `已学习`：实践已经完成，机器验证通过，用户已逐节确认理解。
- `已实现待学习`：实践和机器验证已经完成，但用户尚未逐节确认理解。
- `已规划`：方向、依赖、产物和门禁已确定，尚未开始实现。
- `阻塞`：已经开始，但缺少不可替代的外部条件；必须记录阻塞证据。

禁止使用含糊状态，例如“基本完成”“以后再说”“进行中但不知道差什么”。

一节课的代码已提交不等于用户已学会；一篇 SOP 已写完也不等于生产门禁已通过。

## 6. L01-L33 当前事实

### 阶段一：Tokenizer、Prompt 与 Token Budget（L01-L12）

状态：`已学习`

完成能力：

- Tokenizer 加载、结构检查和 SHA256 身份校验。
- Ollama 模型 metadata 与 prompt template 检查。
- 完整 conversation token 计数。
- 自动历史预算、严格 recent window 和真实 `/chat` 接入。

### 阶段二：Session Summary（L13-L18）

状态：`已学习`

完成能力：

- 连续旧消息选择、触发策略和真实 token 统计。
- Ollama 滚动摘要。
- MySQL version/watermark 保存。
- Summary 与 recent window 共同参与真实 Chat 预算。

### 阶段三：Long-term Memory（L19-L23）

状态：`已学习`

完成能力：

- Memory candidate 校验和真实模型提取。
- 确定性 INSERT、UPDATE、NOOP、FORGET。
- MySQL item/evidence 事务。
- bge-m3 embedding、Qdrant 索引和用户隔离检索。

### 阶段四：Dual Retrieval（L24-L28）

状态：`已实现待学习`

完成能力：

- Memory 与 Document 的 ownership 边界。
- 一次 embedding、并行双路检索和故障隔离。
- 确定性合并、安全渲染和精确 token 子预算。
- 接入真实 `/chat`。

### 阶段五：Production Document Ingestion（L29-L33）

状态：`已实现待学习`

完成能力：

- 文档、版本和稳定 chunk 身份。
- Markdown/Go 结构化切块。
- 幂等 MySQL/Qdrant ingestion。
- Snapshot、Alias、验证、切换和回滚。
- Golden Retrieval Evaluation 与 scope 隔离门禁。

## 7. L34-L78 课程设计

### 阶段六：检索质量工程（L34-L38）

依赖：L24-L33

- L34：生产 Golden Dataset、数据集版本和失败分类。
- L35：字段感知的关键词/BM25 检索。
- L36：Dense + Sparse 混合召回与确定性融合。
- L37：Reranker 与候选多样性控制。
- L38：Score Calibration、动态配额、阈值和检索回归门禁。

实践产物：

- 可版本化的 query、正例、负例、forbidden hit 和问题分类。
- Dense、Sparse、Hybrid、Rerank 的同数据集对比报告。
- 可解释、可回退的线上检索决策策略。

阶段门禁：

- 所有检索优化必须对比固定基线。
- 跨用户和跨 `knowledge_scope` forbidden hit 必须为零。
- 质量提升、延迟和资源成本必须同时记录。

非目标：没有标注数据时，不引入仅凭主观感觉配置的复杂排序模型。

### 阶段七：有依据的回答（L39-L43）

依赖：L34-L38

- L39：证据对象、来源身份与引用契约。
- L40：去重、多样性和位置感知的 Context Packing。
- L41：引用感知 Prompt 与不可信文档边界。
- L42：回答验证、引用核对和证据不足时拒答。
- L43：Faithfulness、Citation Correctness 与 Answerability 评估。

实践产物：

- 稳定的 citation/source 数据结构和 API 输出。
- 引用感知回答、拒答和引用核验实现。
- 可回答与不可回答问题集。

阶段门禁：

- 回答中的引用必须能反查到实际 source/chunk/version。
- 不可回答样例不能通过编造补齐。
- Prompt 或文档中的指令不能改变 ownership 和安全边界。

非目标：不构建通用事实核查搜索引擎，不访问公网补充证据。

### 阶段八：生产级长期记忆（L44-L48）

依赖：L19-L28、L43

- L44：Memory Ontology、别名和 Schema 演进。
- L45：提取 Golden Dataset、召回率与 Confidence 校准。
- L46：异步提取、幂等任务和并发冲突处理。
- L47：MySQL Outbox、Qdrant 同步、漂移扫描与重建。
- L48：旧事实、遗忘和个性化回答的端到端评估。

实践产物：

- 受控 memory key/alias 和版本迁移规则。
- 提取与误提取数据集。
- 可重试 worker、outbox、漂移报告和 rebuild 命令。
- 记忆写入、更新、遗忘和召回质量报告。

阶段门禁：

- MySQL 是唯一事实源，Qdrant 能从 MySQL 重建。
- 重复任务不能重复制造 evidence 或错误推进 version。
- forgotten/stale 事实不能重新参与回答。

非目标：不让 embedding 相似度直接覆盖事实，不把模型自报 confidence 当成概率。

### 阶段九：生产文档管道（L49-L53）

依赖：L29-L38

- L49：Source Registry、连接器契约与文件身份。
- L50：PDF、HTML、Office 等常见格式解析及安全限制。
- L51：扫描文档 OCR、版面结构和表格边界。
- L52：异步 Ingestion Worker、重试、隔离区和背压。
- L53：增量同步、删除传播、血缘和全语料重建验收。

实践产物：

- 统一 source/parser 接口和格式 fixture。
- 解析质量、资源上限和恶意文件测试。
- 可恢复 ingestion job、quarantine 和重放命令。
- source 到 version、chunk、point 的血缘查询。

阶段门禁：

- 单个坏文件不能阻塞整个语料。
- 更新、删除、重试和全量重建结果必须可重复。
- 解析失败不能静默生成看似成功的空文档。

非目标：不在没有样本和质量门禁时支持所有文件格式。

### 阶段十：离线模型与资产供应链（L54-L58）

依赖：L01-L12、L23、L38

- L54：生成、Embedding、Tokenizer 资产清单、来源和 SHA256。
- L55：模型能力注册表、Template、Context 与向量维度。
- L56：离线依赖包、Bootstrap 和可重复环境初始化。
- L57：跨 Runtime 的 Token、Prompt、Embedding 黄金对照。
- L58：模型预热、容量档位、并发限制和模型替换回滚。

实践产物：

- 版本化 model manifest 和资产校验命令。
- 按模型选择 tokenizer、template、context 和 embedding schema 的注册表。
- 可在断网环境使用的安装资产包。
- 兼容性矩阵和硬件容量报告。

阶段门禁：

- 模型、Tokenizer、Template 或向量维度不匹配时启动失败。
- 新机器不得依赖运行时临时下载才能通过验收。
- 模型替换必须通过黄金对照并能够回滚。

非目标：不建立模型训练和 GPU 集群调度平台。

### 阶段十一：运行时可靠性（L59-L63）

依赖：L43、L48、L53、L58

- L59：稳定 API 契约、请求幂等和版本兼容。
- L60：Session 并发、锁、水位和重复任务治理。
- L61：Timeout、Retry、Circuit Breaker 与降级矩阵。
- L62：批处理、缓存、资源配额和工作负载隔离。
- L63：性能基线、压力测试、长稳测试、故障注入和 SLO。

实践产物：

- 版本化 Chat/Ingest/Admin API 契约。
- 并发与重放集成测试。
- 每个外部依赖的失败矩阵。
- 基于参考硬件的容量、延迟和稳定性报告。

阶段门禁：

- 重试和并发不能制造重复事实、重复版本或越权结果。
- 依赖失败必须匹配文档化的硬失败或降级行为。
- SLO 必须明确测试环境和统计方法，不能只记录单次最快结果。

非目标：不追求互联网规模吞吐或跨地域高可用。

### 阶段十二：安全、权限与隐私（L64-L68）

依赖：L43、L48、L53、L59-L63

- L64：威胁模型、信任边界和数据分类。
- L65：认证、授权、用户与 Knowledge Scope 强隔离。
- L66：Prompt Injection、恶意文档与输入资源限制。
- L67：Secret、传输/静态加密、审计与敏感信息处理。
- L68：保留、导出、彻底删除和安全回归门禁。

实践产物：

- 威胁模型和权限矩阵。
- 集中的 principal/ownership 校验。
- 恶意 prompt、恶意文档和越权测试集。
- 数据导出、删除、审计和密钥轮换 SOP。

阶段门禁：

- 越权读取和 forbidden hit 必须为零。
- 删除后不得从 MySQL、Qdrant、summary、cache 或备份恢复路径意外重新出现。
- 安全门禁失败阻断发布，不允许 warning 降级。

非目标：不实现公网身份平台、组织计费和复杂企业审批流。

### 阶段十三：可观测与可恢复运维（L69-L73）

依赖：L59-L68

- L69：结构化日志、Correlation ID 与审计事件。
- L70：Metrics、Tracing、Token、检索和模型延迟指标。
- L71：Health、Readiness、依赖诊断与告警。
- L72：MySQL、Qdrant、源文件和配置的备份恢复。
- L73：事故手册、数据对账、修复命令和恢复演练。

实践产物：

- 一次请求跨 Chat、Retrieval、Model、Store 的关联信息。
- 关键 SLI、告警规则和依赖状态。
- 版本化备份清单和实际恢复报告。
- 常见事故 runbook、对账和 repair 命令。

阶段门禁：

- 关键故障必须能被发现并定位到具体依赖或数据阶段。
- 备份只有在干净环境完成恢复演练后才算有效。
- repair 命令必须可预览、幂等并保留审计记录。

非目标：不建设通用监控平台；优先输出标准指标并复用成熟组件。

### 阶段十四：交付、升级与最终验收（L74-L78）

依赖：L01-L73

- L74：配置分层、Schema Migration 和兼容性策略。
- L75：可重复构建、SBOM、许可证、校验和与离线发布包。
- L76：Linux 单机/小型内网部署和全新环境冷启动。
- L77：版本升级、数据迁移、模型替换与回滚演练。
- L78：生产验收 Boss 战。

实践产物：

- 可审计 migration 和升级顺序。
- 带 checksum、SBOM、license 清单和版本说明的离线发布包。
- 干净 Linux 环境部署记录。
- 升级、失败回滚和数据兼容报告。
- 最终生产验收报告和运行手册。

阶段门禁：

L78 必须在干净环境依次证明：

1. 离线安装和启动。
2. 导入、更新、删除并重建真实语料。
3. 运行检索和回答质量评估。
4. 执行多用户并发对话并证明隔离。
5. 模拟 Ollama、Qdrant、MySQL 和 worker 故障及恢复。
6. 完成备份恢复。
7. 完成一次版本升级与回滚。
8. 输出可由另一位工程师执行的验收报告和运行手册。

非目标：不把“进程启动成功”或“演示请求返回 200”当成生产验收完成。

## 8. 蓝图变更规则

L01-L78 可以调整，但必须保留变更理由。

允许调整的证据：

- 真实 Golden Dataset 结果。
- 可复现故障、性能或容量数据。
- 新的安全、合规或部署要求。
- 前置课程证明原有章节顺序无法实施。

不允许的理由：

- 某项技术流行。
- 只想增加课程数量。
- 没有样本却预设某个模型一定提升质量。
- 为了让状态好看而降低验收门禁。

新增课程时优先插入新的阶段，不随意重编号已被教学记录引用的课程。若必须重编号，
必须提供旧编号到新编号的迁移表。

## 10. 验证设计

完成文档更新后必须运行：

1. 课程编号检查：L01-L78 每个编号恰好出现一次于权威逐课清单，无缺失、无重复。
2. 状态检查：L01-L23 为 `已学习`，L24-L33 为 `已实现待学习`，L34-L78 为 `已规划`。
3. 链接检查：本次修改文档中的仓库内 Markdown 链接均指向存在的文件或锚点。
4. 一致性检查：世界地图、蓝图、学习状态和 handoff 对当前坐标及终点描述一致。
5. 范围检查：Git diff 不包含 Go、SQL、Shell、测试和小白课程文件。
6. 人工自审：无 `TODO`、`TBD`、旧仓库绝对路径和“真实 Qdrant/Ollama 尚未开放”等过时描述。

这些检查证明文档蓝图自身完整，不代表 L34-L78 的生产能力已经实现。
